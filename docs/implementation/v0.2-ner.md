# v0.2 implementation write-up

Consolidates the plan (`docs/plans/2026-09-24-v0.2-ner.md`), the decisions
made while executing it, the controller rulings recorded in the SDD ledger
(`.superpowers/sdd/2026-09-24-v0.2-ner/progress.md`), and the Task 25
verification. The spec (`docs/specs/2026-09-24-lexicon-design.md`) and the
plan file stay as history; this document is the current summary of what
v0.2 (dictionary NER) actually is. It builds on
[`docs/implementation/v0.1-analysis.md`](v0.1-analysis.md) (text analysis:
`textnorm`, the dictionary `Registry`, `Analyzer`), unchanged by this task.

New dependency: `go.yaml.in/yaml/v3` (v3.0.5), required directly, used by
`rules` for YAML rule files. No other dependency changed.

## What was built, by package

### `gazetteer`

Compiles dictionary aliases into token tries and matches them against
analyzed text; does not decide between overlapping matches (that is `ner`'s
job).

- `Entry`, `EntryFlag` (`RequiresContext`, `SurfaceOnly`, `CaseSensitive`,
  `Blocked`), `Source` (`deps.go`).
- `TSVSource` (`tsv_source.go`): a `# key: value` manifest header, one entry
  per line, from a file or (`NewTSVSourceData`) from in-memory data for
  embedding hosts; a malformed line is listed in the build report, not a
  fatal error. `SliceSource` (`slice_source.go`) for entries built in Go.
- A process-wide append-only interner (`interner.go`): every lemma and
  surface string becomes a `uint32` ID; an unknown lemma is ID 0.
- `builder.go`/`trie_builder.go`/`trie.go`: each source compiles into a
  lemma trie (token sequences of lemma IDs, ambiguous tokens expanded to at
  most `MaxLemmaKeys` combinations, capped at 8) and a surface trie (token
  sequences of normalized surface forms), both with sorted child arrays.
- `match.go`/`text.go`: matching walks from every token, follows lemma
  alternatives, and stops at the longest alias or a sentence end; overlaps
  between aliases are all reported (`TestMatchDoesNotAllocate` pins the walk
  at zero allocations per call).
- `groups.go`/`groups_builder.go`: variant groups key by `(source, Ref)`;
  `Canonical(key)` and `Expand(lemma)` map between an alias and the group it
  belongs to.
- `snapshot.go`/`gazetteer.go`: an immutable `Snapshot` behind an
  `atomic.Pointer`, swapped by `Refresh`/`RefreshSource` keyed on
  `Source.Version()`; a failing rebuild keeps serving the previous snapshot
  (`TestBuildKeepsPreviousOnFatalError`). The build report
  (`source_report.go`) counts entries, aliases, keys, capped combinations
  and blocked entries, records duration, and lists per-line errors.
- `TypeProfiles` (`config.go`): per-entry-type dictionary profile, so a
  place gazetteer and a person-name gazetteer can use different morphology
  profiles in one `Gazetteer`.

### `rules`

YAML/JSON rule books: hints (lemma keywords near a gazetteer match) and
triggers (lemma keywords that create a candidate span on their own),
grouped into tag-gated rule sets.

- `RuleSet`/`When` (`rule_set.go`), `Hint` (`hint.go`, `hint_rule.go`),
  `Trigger` (`trigger.go`, `trigger_rule.go`), compiled into a `Book`
  (`book.go`) by `Compile`.
- `Load`/`LoadNamed`/`LoadFile` (`load.go`, `file.go`) read YAML
  (`go.yaml.in/yaml/v3`) or JSON, with a top-level `meta:` manifest.
  `LoadNamed(name, r)` names the source for errors (`Load(r)` uses the
  unnamed `<input>`, `LoadFile(path)` names the path). A second pass over
  the parsed `yaml.Node` tree (`positions.go`) records the source line of
  every rule set, hint and trigger — a struct-level `UnmarshalYAML` with
  `KnownFields` would lose that information — so `Load` errors read
  `<file>:<line>: <message>` and `Compile` errors read
  `<file>:<line>: <set>/<rule>: <message>` (`rule_error.go`). JSON input
  gets line numbers too.
- `keyword.go`: a compiled `"a|b|c"` lemma alternation. Every alternative is
  normalized with `textnorm.NormalizeWord(textnorm.PreReform, …)` regardless
  of the orthography rules the analyzer used to produce the term being
  matched, so a rule keyword written in modern spelling still matches
  pre-reform forms and vice versa; a dotted keyword's trailing dot is
  trimmed before comparing, because `Analyzer.fullTerm` gives a dotted
  abbreviation term a `Form` that carries the dot (e.g. `"ул."`) while
  keyword alternatives never do.
- `window.go`/`shape.go`/`shape_check.go`/`direction.go`: the window is
  measured in content words from the keyword to the span, in the rule's
  direction, and does not cross punctuation or a sentence end (the dot of
  a dotted abbreviation does not break it). A hint applies to spans
  of its type within the window; a trigger collects up to `Window.Max`
  words after (or before) its keyword. A trigger's `Shape` (case/script)
  and `StopAt` restrict the words it covers (`TriggerRule.Accepts`), not
  the keyword; hints have no shape.
- `stop_set.go`/`active.go`/`compiled_set.go`: a rule set is active only
  when the document carries ALL of its `When` tags; an empty `When` is
  always active. `Book.Active` returns rules shared with the book; callers
  must not modify them.

### `ner`

The extraction pipeline: gazetteer matches plus rule hints/triggers,
filtered, scored, and resolved into non-overlapping spans.

- `Doc`, `Span`, `SpanFlag`, `Result`, `Config` (weights, `Nesting`),
  `New`/`Extract`, `Explain` (public API — `document.go`, `span.go`,
  `span_flag.go`, `result.go`, `config.go`, `pipeline.go`, `option.go`).
  `Pipeline.Extract` pins one gazetteer snapshot per call, so a concurrent
  `Refresh` never changes the gazetteer an in-flight call matches against
  (`TestExtractConcurrentWithRefresh`, `TestExtractConcurrentWithChangingSource`).
  Only the snapshot is pinned: the analyzer and the dictionary registry
  behind it are live, and the snapshot may have been compiled with an older
  analyzer until the host calls `Refresh` (see `ner/doc.go`).
- `Result.Version` hashes a constant extractor version (`extractorVersion`
  in `pipeline.go`, bumped on any behaviour change of extraction), the
  analyzer version, `Snapshot.Version` (sources, analyzer and the
  gazetteer's `TypeProfiles`/`DefaultProfile`), `Book.Version` and the
  pipeline configuration (weights, `MinLemmaMatchRunes`, `Nesting`, the
  document `Profiles` and `DefaultProfile`). `ner.New` and `gazetteer.New`
  deep-copy the host's maps (profiles, nesting, type weights).
- Extract is linear in the document size: hints and triggers look up
  candidates in a position index (`pos_index.go`; a window is at most
  `rules.MaxWindow` words), alternatives are bucketed by range, and the
  nesting resolver binary-searches the end-sorted candidates. The context
  is checked between pipeline stages.
- `filters.go`: drops a candidate that is `Blocked`, that needs
  `RequiresContext` but no hint or trigger supported it, or that is
  `CaseSensitive` and the words' case does not match. `MinLemmaMatchRunes`
  drops only one-word, lemma-only hits, measured on the alias's
  `SurfaceKey`. Filtering recomputes each candidate's origin (the
  hits actually kept) so a later score reflects only the surviving
  evidence, not the pre-filter match.
- `hints.go`/`triggers.go`: a hint boosts or absorbs an adjacent gazetteer
  candidate; a trigger creates a candidate of its own type where none
  existed, from its keyword's window alone. A trigger candidate is refused
  when its collected words overlap a `Blocked` range of the same type —
  `Blocked` means "these words are not of type X", and a trigger must
  respect that the same way a gazetteer match does. A negative trigger
  subtracts its weight from overlapping gazetteer candidates of its type;
  it never affects trigger candidates (see Known limitations below). A
  keyword absorbed by a hint or trigger does not make the span
  `Ambiguous` (the rule disambiguated it) but still marks it `Abbrev`.
- `score.go`/`weights.go`: a candidate's score is a weighted sum (decision
  D6): per word, the origin weight (surface, lemma or trigger) plus the
  type weight; a length bonus per word beyond the first; the hint/trigger
  evidence; minus an ambiguity penalty per extra ref or normal form. It is
  not a lexicographic order. Scores are rounded to 1e-6 once (`scoreAll`)
  so every later comparison (sorting, the interval-scheduling take/skip
  choice, tie detection) compares rounded
  values exactly — floating-point epsilon comparisons are not transitive
  and would break the "ties resolved by type name" rule.
- `resolve.go`/`selection.go`: weighted interval scheduling over candidate
  ranges — no two chosen spans cross, and one range may nest inside another
  only for a `Config.Nesting` outer/inner pair the host declared. Losing
  candidates of another type on the same exact range become the winner's
  `Span.Alternatives` (best first); a tie in score is never silent — it
  sets a flag on the span. Tie detection compares score alone, not
  score-plus-nesting-value, which is deliberate but means two candidates of
  different types that happen to need distinct nesting configurations for
  the same range could show a spurious "tie" (an edge case, not observed in
  the golden set).
- `Doc.Types` is applied last, after resolution, so a type filter never
  changes which span wins a range — it only hides spans of unwanted types
  from the result.

### `nertest`

A golden-JSONL test harness for `ner.Pipeline`.

- `Case` (`case.go`): a JSONL golden case (text, tags, expected spans) plus
  `Context map[string]string` (JSON `context`, optional) — host document
  metadata that lexicon itself ignores.
- `Run(ctx, ex, cases, opts ...Option)` (`run.go`, `run_config.go`,
  `option.go`): extracts every case and scores it against its expected
  spans, both strictly (exact range and type) and partially (overlap
  counts); `WithTags(func(Case) []string)` appends derived tags to the
  extraction call only (the `Case` value is not modified), letting a host
  turn `Context` into rule-set tags, e.g. `{"estate": "peasant"}` →
  `"estate:peasant"`.
- `Counts`/`type_score.go`: per-type precision, recall and F1 (harmonic
  mean of precision and recall), both strict and partial; `Report.Write`
  formats them as a table; `Report.Check(minPrecision, minRecall)` lists
  the types below a threshold.

### `cmd/lexicon`

- `lexicon extract [--dicts DIR] [--ortho modern|prereform] [--gazetteer
  FILE...] [--rules FILE...] [--nest outer>inner...] [--tags T,...]
  [--types T,...] [--explain] [--format table|jsonl] TEXT...|-`: runs the
  NER pipeline over CLI arguments or stdin (`-`, one document per line).
  Follows the `analyze` command's conventions (`--dicts`/`--ortho` shared
  through `pipelineFlags`, a `Close` error joined into the command's
  result, never dropped).
- `lexicon golden [--dicts DIR] [--ortho modern|prereform] [--gazetteer
  FILE...] [--rules FILE...] --cases CASES.jsonl [--min-precision N]
  [--min-recall N]`: runs a golden case set and reports strict/partial
  precision/recall/F1; a check below threshold is a plain error (exit 1).
  `Case.Context` is ignored — `golden` calls `nertest.Run` without
  `WithTags`.
- `run(ctx, args, stdin io.Reader, stdout, stderr) int` returns the exit
  code and gained the `stdin` parameter (needed by `extract -`); each
  subcommand (`runAnalyze`, `runExtract`, `runGolden`, `runDicts`) returns
  an `error` that `run` maps to the exit code.

## Behaviour decisions made during implementation

Points where the plan's own text was incomplete or ambiguous, resolved
while implementing (see the SDD ledger for the underlying discussion):

- **Blocked vs. filter timing.** A candidate that survives an early filter
  pass and is boosted or absorbed by a later hint must be scored on the
  evidence it actually kept, not the evidence it had before filtering — so
  both the early filter and the context filter recompute a candidate's
  origin through one shared helper, instead of the plan's filter code (which
  left a stale origin after filtering).
- **Exact float ties.** Scores are quantized once, to 1e-6, right after
  scoring; every later comparison (sorting, the scheduler's take-vs-skip
  choice, tie detection) compares the rounded values exactly, with no
  epsilon anywhere. An epsilon comparison used inconsistently across three
  different call sites is not transitive and would silently break which
  candidate a same-range tie resolves to.
- **Blocked ranges veto trigger candidates too.** `Blocked` means "these
  words are not of type X" (spec line 597), so a trigger must not create a
  type-X candidate over words already vetoed for type X by a blocked
  gazetteer entry — the plan's original trigger code checked `Blocked` only
  on gazetteer-sourced candidates and let a trigger bypass it.
- **Rule keywords normalize with pre-reform orthography** regardless of the
  document's own orthography setting, so one rule file works for both
  modern and pre-reform text; a keyword's trailing abbreviation dot is
  trimmed before comparing, matching how `Analyzer.fullTerm` writes a dotted
  abbreviation's `Term.Form`.
- **CLI subcommand signature.** v0.1's CLI dispatched with a `switch`, not
  a table, and its `run` returned an `int`; v0.2 keeps both. Subcommands
  return an `error`, which `run` maps to the exit code (nil/`ErrHelp` → 0,
  a `usageError` → 2 with usage text, anything else → 1); `run` gained the
  `stdin io.Reader` parameter `extract -` needs.
- **`--dicts`/`--ortho` defaults match `analyze`**: `--dicts` defaults to
  the same directory `analyze`/`dicts` use, and `--ortho` defaults to
  `"modern"`, for CLI consistency across subcommands.

## Review fixes (2026-09-26)

A documentation review against the code found four behaviours that did
not match the spec or the documentation; the owner decided to change the
code (0.2 is unreleased, so `extractorVersion` stays `ner-1`):

- **`Ambiguous` from covered words** — set only for an ambiguous
  abbreviation no rule absorbed (`ambiguousAbbrev`), not for any word with
  several lemmas: ordinary homonymy flagged most spans on the real base,
  and the spec defines the flag by refs, normal forms and ties.
- **Trigger weight on candidates** — a proposed candidate gets the rule's
  `Weight` as evidence, like a boosted span; before, rule files could not
  tell a strong trigger from a weak one.
- **Trigger absorb on boost** — a boosting trigger with `Absorb` extends
  the gazetteer span over an adjacent keyword, as a hint does, so span
  ranges no longer depend on whether the gazetteer knows the name.
- **`extract -`** — stdin lines are no longer trimmed, so offsets refer to
  the line as read (the offsets contract).

Q-v02-10 (`absorb`) now covers both hints and triggers.

## Open questions

Of the plan's Q-v02-1 through Q-v02-12 and Q-CLI-1/2:

- **Resolved during execution**: Q-v02-1 (constant names — code uses the
  prefixed v0.1 names throughout), Q-v02-6 (cross-type ties on the same
  range — the winner carries losing types as `Span.Alternatives`),
  Q-v02-11 (rule-file error line numbers), Q-CLI-2 (the CLI subcommand
  signature — see above).
- **Answered by existing v0.1 behaviour**, no v0.2 decision needed:
  Q-v02-2 (`lexicon.Dictionaries` already has `Version()`), Q-v02-3
  (`gazetteer.Alternatives` handles an unknown word as either no lemmas or
  one `FlagUnknown` lemma — both v0.1 shapes), Q-v02-4 (`SentenceEnd` is set
  on the `.`/`!`/`?`/`;`/`…` token itself, not the following word).
- **Settled as a default, open to revisit**: Q-v02-5 (`Blocked` vetoes an
  exact range and type, including trigger-created candidates over that
  range — see "Behaviour decisions" above), Q-v02-7 (nesting defaults are
  empty; hosts opt in per outer/inner type pair via `Config.Nesting`),
  Q-v02-10 (the hint/trigger `Absorb` field is an extension beyond the
  spec; shipped under that name, not re-confirmed by the owner).
- **Still open, for the owner**:
  - Q-CLI-1: should `extract`/`golden` read a `--profiles FILE` (same
    format family as rule files) instead of the one hard-coded `"text"`
    profile they use for every document and alias type?
  - Q-v02-8: should `Pipeline` gain a `SetRules` (atomic pointer) for rule
    hot-reload, or is rebuilding the pipeline to change rules acceptable?
  - Q-v02-9: is a process-wide interner that never shrinks acceptable for
    long-running hosts with heavy alias churn?

## Known limitations / follow-ups

User-visible or design gaps worth carrying into v0.3 planning or a host's
own testing, taken from the ledger's deferred minors:

- A span ending in a dotted abbreviation currently excludes the dot (e.g.
  the gazetteer surface for "Калужской губ." comes back as "Калужской губ",
  without the trailing dot) — candidate fix for v0.3 (extend the span end
  over the abbreviation's dot); left alone in v0.2 because changing span
  ends now would have moved the golden-set expectations built in Tasks
  22–24.
- A trigger's context window can swallow a following name of a different
  type before that name's own candidate is considered (e.g. a place trigger
  window absorbing a person name that immediately follows) — a design
  trade-off, not a bug, but worth flagging to a host tuning trigger
  windows.
- A negative trigger subtracts weight only from gazetteer candidates; it
  never affects a trigger-created candidate.
- `Blocked` vetoes regardless of the entry's other flags: a blocked
  `CaseSensitive` entry vetoes whatever the letter case, and a blocked
  one-word lemma match vetoes even below `MinLemmaMatchRunes`.
- A later hint measures its window from the span's current edge, which an
  earlier hint may have moved by absorbing its keyword; results can
  depend on the order of hints.
- A `Refresh` cancelled through its context discards the sources it had
  already rebuilt in that call; nothing is published, and the next call
  rebuilds them again. A source whose `Version` fails keeps its data, with
  the error in its report.
- `TSVSource` manifest keys are limited to `[a-z_]`; a `# Key: value` line
  with any other key is a plain comment.
- The CLI (`extract`, `golden`) configures only the `"text"` profile, so a
  golden case with `"profile": "name"` aborts the run with
  `ner.ErrUnknownProfile`; gazetteer sources are named after the file
  basename, so two `--gazetteer` files with the same basename fail as a
  duplicate source name.
- The process-wide interner is append-only and never shrinks; see Q-v02-9
  above.
- There is no integration-tagged `ner` test against the real OpenCorpora
  base dictionary yet (v0.1 has one for `Analyzer`); a gap that would only
  surface once a host runs `ner` against real morphology.
- `TestExtractConcurrentWithRefresh` refreshes an unchanging source;
  `TestExtractConcurrentWithChangingSource` flips a source between two
  contents and checks that every result equals one of the two known
  outputs (spans and version together), so tearing is detected by the
  test itself, not only by `go test -race`.
