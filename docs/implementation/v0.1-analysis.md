# v0.1 implementation write-up

Consolidates the plan (`docs/plans/2026-09-24-v0.1-analysis.md`,
`docs/plans/2026-09-24-v0.1-analysis-lexicon.md`), the decisions made while
executing it, the controller rulings recorded in the SDD ledger
(`.superpowers/sdd/2026-09-24-v0.1-analysis/progress.md`), and the review
fixes applied along the way. The spec (`docs/specs/2026-09-24-lexicon-design.md`)
and the two plan files stay as history; this document is the current summary
of what v0.1 actually is.

Gomorphy version actually used: **v1.2.0**, released and required directly in
`go.mod` (`github.com/amarin/gomorphy v1.2.0`) — no `go.work`, no `replace`,
no pseudo-version. The preflight ruling confirmed the tag exists on
proxy.golang.org before Task 5 first imported it.

## What was built, by package

### `textnorm`

Orthography rule sets and tokenization, no dictionaries.

- `Rules` (`case.go`, `script.go`, `rules.go`): `Modern` and `PreReform` rule
  sets, each with a `Version` string (bumped to `"2"` by decision D5 — the
  homoglyph rework); `Case` (`CaseNone`, `Lower`, `Title`, `Upper`, `Mixed`),
  `Script` (`ScriptCyrillic`, `ScriptLatin`, `ScriptMixed`, ...).
- `Tokenize(r Rules, input string) []Token`: emits `Token{Kind, Raw, Form,
  Start, End, RuneStart, RuneEnd, Script, Case, Dotted, SentenceEnd}` for
  every word, number, punctuation and symbol token, offsets computed in one
  pass on the input exactly as passed (`input[Start:End] == Raw`), token
  boundaries on grapheme-cluster boundaries (an approximation without new
  dependencies: combining marks, format characters except U+200B, emoji
  modifiers/ZWJ sequences and regional-indicator pairs extend/join the
  preceding cluster — not modelled: Unicode `Prepend`, Hangul syllable
  rules).
- `SplitHyphen(t Token) []Token`: hyphen parts of a `Word` token, nil for a
  token without an inner hyphen.
- `UTF16Offsets(input string, byteOffs ...int) []int`: UTF-16 code-unit
  offsets for a set of byte offsets.
- `Orthography(r Rules, s string) string` / `NormalizeWord`: apply a rule
  set's letter maps and homoglyph folding to a string/token form.
- `ReformVariants(form string) []string`: pre-reform ending variants of a
  modern word form, used by the analyzer's dictionary lookup.

### `lexicon` (root package)

- `Registry` (`registry.go`, `snapshot.go`, `dict.go`, `load.go`,
  `registry_state.go`): `Open(ctx, Options) (*Registry, error)`, `Parse(word
  string, kinds []Kind) []Reading`, `Version() string` (sha256 over name,
  kind, content hash of enabled loaded dictionaries in registry order),
  `List() []Entry`, `Summary() string`, `SetEnabled(ctx, name, on) error`,
  `Reload(ctx) error`, `Close() error`. Loads host built-ins
  (`Options.Builtin`) and `<kind>.<name>.dat|tsv` files from `Options.Dir`
  with `.meta` provenance sidecars (`Manifest`, `ParseManifest`,
  `mergeManifest`); a broken file is listed with its error and does not
  fail `Open`/`Reload`; hot reload swaps an immutable `snapshot` atomically,
  retiring the old one only after in-flight `Parse` calls finish
  (reference-counted `dict.retain`/`release`).
- `Options` (`options.go`): `Dir`, `Base []byte` + `BaseManifest Manifest`
  (an embedded base with its own provenance sidecar, decision D26/Q11),
  `Builtin []BuiltinDict`, `Kinds []Kind` (declared-kinds allow-list, owner
  decision 7/D17 — nil accepts any valid kind), `State StateStore`.
- `Kind`, `KindBase`, `KindAbbrev`, `kindSet` (`kind.go`, `kind_set.go`).
- `Profile{Name, Kinds, Grammemes}` (`profile.go`): host-defined dictionary
  and grammeme filter, keyed by `Name` for the lemma cache.
- `Analyzer` (`analyzer.go` + `analyzer_*.go`): `NewAnalyzer(Dictionaries,
  textnorm.Rules, AnalyzerOptions) *Analyzer`, `Analyze(text string, p
  Profile, m Mode) []Term` with `ModeIndex` (genodex search P1 behaviour —
  ported P1 tests as regression tests) and `ModeFull` (exactly one `Term`
  per token, 1:1 with `Tokenize`, for NER), `Version() string`,
  `ParseQuery(q string, p Profile) Query`. Abbreviation lookup
  (`analyzer_abbrev.go`), stop-word detection by gomorphy POS
  (`grammeme.go: allStop`, `hasGrammeme` — local helper, not gomorphy
  1.3.0's `HasGrammeme`, decision D27), a per-analyzer LRU lemma cache
  (`lru.go`, `lemma_cache.go`, keyed by `Profile.Name` + dictionary
  `Version()`, dropped on version change).
- `Term`, `Lemma`, `Flag` (`FlagAmbiguous`, `FlagPredicted`, `FlagUnknown`,
  `FlagAbbrev`, `FlagStop`, `FlagReform`), `Reading`, `Query`.
- `StateStore`, `Dictionaries` interfaces in `deps.go` (no mockgen,
  decision D24 — hand-written fakes in `*_test.go`); `MemState` — the
  in-memory default (`Options.State == nil`).
- `BuiltinDict{Name, Kind, Format, Data, Manifest}`.

### `basefetch`

- `Fetch(dst string) (version string, err error)`: downloads
  pymorphy2-dicts-ru via gomorphy's `pymorphy.Loader`, compiles it with
  `morphology.OpenPyMorphyDense`, and saves it plus a `.meta` provenance
  sidecar (`Source`, `License: "CC BY-SA 4.0"`, `Version`, `URL`,
  `GeneratedFrom`) atomically next to `dst`. `DefaultName =
  "base.opencorpora.dat"`.
- Isolated from the root package's "no logger" rule because it imports
  gomorphy's pymorphy loader (which pulls `amarin/logging` and zap) —
  see **Concern: `dicts fetch` panics** below, found while executing this task
  and since fixed (`ensureLogging` in `basefetch/logging.go`).

### `cmd/lexicon`

- `lexicon analyze [--dicts DIR] [--ortho modern|prereform] [--profile
  NAME[:KIND[G1|G2],KIND...]] [--mode index|full] TEXT...`
- `lexicon dicts list [--dicts DIR]`
- `lexicon dicts fetch [--dicts DIR] [--force]`
- Dictionary dir default: `$LEXICON_DICTS`, else
  `$XDG_DATA_HOME/lexicon/dicts`, else `~/.local/share/lexicon/dicts`. The
  CLI passes `Kinds: nil` (accepts every valid kind — it has no host
  vocabulary). `fetch` is called through a package-level `var fetch =
  basefetch.Fetch` seam so tests can fake it without the network (Task 15
  review fix).

## Decisions and deviations from the spec/plan

The plan's own decision table (D1–D28), unchanged by execution except where
noted:

| # | Spec says / is silent on | Plan does | Why |
|---|---|---|---|
| D1 | Package `lexicon` in module `github.com/amarin/lexicon` | Root package is `lexicon` (no `lexicon/lexicon` stutter) | Import path reads `lexicon.Registry`; subpackages unaffected |
| D2 | `Script` has `Mixed`; `Homoglyphs` («Kот», «Iоаннъ») | Owner decision 2026-09-24 (Q1): within one hyphen part of a word, if the part has a Cyrillic letter and every other letter is a key of `Rules.Homoglyphs`, the part is Cyrillic — one `ScriptCyrillic` word, homoglyphs replaced in `Form`, `Raw`/offsets untouched («Kот» → `Form` «кот»). Other parts split at Cyrillic/non-Cyrillic boundaries as in P1 («Kотw» → «K» + «от» + «w»); parts without Cyrillic letters unchanged («XIX-го»). `ScriptMixed` = a non-Cyrillic run that is not purely Latin | Homoglyphs are an OCR/typing issue, so both rule sets apply them. Intentional `ModeIndex` change: P1 indexed «от» in «Kот», lexicon indexes «кот» |
| D3 | `Case`: Lower, Title, Upper, Mixed | Adds `CaseNone` (zero value); `TokenKind` starts at 1 | Zero values must not claim a kind/case |
| D4 | U+2010 → `-` listed under `PreReform` | Also in `Modern` | Typographic, not orthographic |
| D5 | `Homoglyphs`: Latin look-alikes inside Cyrillic words | Common table (A a B C c E e H K k M O o P p T X x y Y) in both rule sets; `PreReform` adds `i→і`, `I→І`. Folding applies before lower-casing so upper-case-only homoglyphs fold too. Both rule sets get `Version` "2" | «Mississippi», «XIX», «MOCKBA», «HOME» (no Cyrillic letter) stay Latin — confirmed intended (Q10) |
| D6 | `Form` "" for punctuation | Also "" for `Symbol`; `Number` form = its ASCII digits | Symbols carry no lemma |
| D7 | `SentenceEnd`: '.', '!', '?', ';' or line break | Set on `.` `!` `?` `;` `…` always, and on the last token before a blank line/U+2029; a single line break is a space (Q2) | Hard-wrapped archival text must not split multi-word matches |
| D8 | Grapheme-cluster boundaries | Approximation without new deps (see textnorm above) | Spec forbids deps beyond gomorphy/x/text |
| D9 | `SplitHyphen(t Token) []Token` | Returns nil for a token without an inner hyphen | Callers can tell "no parts" from "one part" |
| D10 | `Dictionaries` interface with `Parse(word, kinds)` | Adds `Version() string` | Cache invalidation needs the dictionary-set version |
| D11 | Parse rules live in the registry | `Registry.Parse` applies them and `Analyzer` re-applies them (drops non-base predictions) | Any `Dictionaries` fake/host gets P1 semantics |
| D12 | Flag `Reform` | Set whenever a lemma came from a pre-reform ending variant; P1 expectation `покровскаго=покровский[]` becomes `…[reform]` | Additive |
| D13 | P1: parts of a compound carry the whole token | `ModeIndex` part terms carry `SplitHyphen` part tokens (precise offsets) | Better snippet offsets |
| D14 | One-letter abbreviations only with a dot, `Ambiguous` (P1 did not enforce) | Enforced | genodex `normalization.md` rule |
| D15 | `ModeFull` keeps every token | Exactly one `Term` per token, hyphenated words not expanded | NER indexes terms by token index |
| D16 | — | Abbreviation lookup ignores profile kinds (P1 parity) | See open question Q3 below |
| D17 | `<kind>.<name>.dat\|tsv`, kind `[a-z][a-z0-9_]*` | Declared kinds (owner decision 7): `Options.Kinds` allow-list; nil = accept any valid kind | No silent fallback; a typo is visible in `List()` |
| D18 | A file `base.<name>.*` in Dir replaces the built-in base | Any `base.*` file drops the built-in base (named `base.builtin`) | As spec |
| D19 | — | A missing `Options.Dir` is an empty directory, not an error, and is not created | Library should not create host directories |
| D20 | `Profile{Name, Kinds, Grammemes}` | Empty `Kinds` = all dictionaries; cache keyed by `Profile.Name`, empty name disables caching | Defines corner cases |
| D21 | `Entry` "info"; `BuiltinDict{Name, Kind, Data, Format}` | `Entry.Manifest Manifest` + `Entry.Format`; `BuiltinDict.Manifest` added | Structured provenance |
| D22 | gomorphy F: `Parse` strings "expected to be copies — verify" | `Registry.Parse` defensively `strings.Clone`s `Normal`/`Tag` | Cached lemmas outlive retired dictionaries — see open question Q5 |
| D23 | `Reload` rescans and rebuilds | Reopens every dictionary (no reuse by hash) | Simple; reuse is an optimisation — see open question Q6 |
| D24 | deps.go with `//go:generate mockgen` (genodex) | Interfaces in `deps.go`, no mockgen, hand-written fakes | Spec: tests stdlib only |
| D25 | CLI `--profile P`, `--ortho prereform` | `--profile NAME[:KIND[G1\|G2],KIND…]`; `--ortho modern\|prereform` default modern; `--mode index\|full` default index | Profiles are host config; CLI needs a textual form |
| D26 | Manifest sidecar | `basefetch` writes `base.opencorpora.dat.meta`. Built-in base (owner decision 2026-09-25, Q11): hosts embed the `.meta` too and pass it as `Options.BaseManifest`; `base.builtin` merges it over gomorphy `BuildInfo` | Attribution travels with an embedded file too |
| D27 | "Grammeme checks use gomorphy `HasGrammeme`, falling back …" | v0.1 uses only the local helper `hasGrammeme` | gomorphy 1.3.0 not released at plan time; swap later without API change |
| D28 | gomorphy D (`CharPolicy`) not required | TSV `ё→е` replacement at load kept from P1 | Works with or without D |

  `~/dev/mine/lexicon` on branch `main`, not in a separate worktree/branch —
  the plan's worktree instructions were dropped mid-flight.

### Review fixes applied along the way

- **`mergeManifest` `Extra` aliasing** (Task 13, controller ruling):
  `mergeManifest` previously could leave the merged manifest's `Extra` map
  aliased to the primary's backing map when the fallback's `Extra` was
  empty (a struct copy copies the map header, not its contents), so
  mutating a merged manifest silently mutated the primary. Fixed to always
  return an independent map; `TestMergeManifestExtraIndependent` added.
- **`basefetch` finalize order** (Task 12): the plan originally wrote the
  `.meta` sidecar to its final path before renaming the `.dat` into place,
  so a rename failure could leave a `.meta` with no matching `.dat`. Fixed
  to write both to `.tmp` files, rename the `.dat` first, then the
  `.meta`; any error removes the temp files. A `.dat` without a `.meta` is
  acceptable (the registry falls back to gomorphy `BuildInfo`); a final
  `.meta` without its `.dat` must never happen.
- **`Registry.SetEnabled` duplicate names + no-leak test** (Task 14): a
  duplicate-name entry (e.g. a `.dat` and `.tsv` file for the same
  `<kind>.<name>`, one loaded and one an error) made name-keyed
  `SetEnabled` ambiguous; fixed to update every same-name entry. Added a
  hook-based test proving no dictionary is left open/leaked across
  `Reload`/`Close` even with an in-flight `Parse` racing the swap
  (`testHookDictClosed`).
- **CLI `Close` errors surfaced + fetch tests via seam** (Task 15): a
  `Registry.Close` error from the `dicts list` path was previously dropped;
  now joined into the command's return error. `fetchBase`/`dicts fetch`
  gained tests that fake network access through the `var fetch =
  basefetch.Fetch` seam, and `dicts list --force` (a flag that does not
  exist for `list`) is now rejected instead of silently ignored.
- **Zero-width/invisible escapes in Go literals** (Task 1, carried through
  every task with literal test fixtures): raw ZWSP/ZWJ/combining-mark
  characters must never appear raw in a Go literal (constraints.md); the
  tool-call transport decodes typed `\uXXXX` back into raw characters, so
  such fixtures were generated with a small script emitting literal
  backslash-`u` sequences and verified with the constraints.md grep
  (`LC_ALL=C grep` for the UTF-8 byte sequences of U+200B–U+200D, U+2060,
  U+FEFF, U+00AD, U+2028/2029) — empty on every check.
- **Rule-set `Version` bumped to `"2"`** (D5, Task 7/15 rulings above):
  every place that hard-coded a rule-set version string in a test
  (`TestAnalyzerVersion`, `main_test`) was updated once, not patched
  per-task.

### Concern: `lexicon dicts fetch` panics (found while executing Step 2)

`go run ./cmd/lexicon dicts fetch --dicts "$D"` panics instead of
downloading:

```
panic: logging: set backend first

goroutine 1 [running]:
github.com/amarin/logging.NewNamedLogger(...)
	.../github.com/amarin/logging@v0.1.2/logging.go:124 +0x270
github.com/amarin/gomorphy/pkg/pymorphy.NewLoader(...)
	.../github.com/amarin/gomorphy@v1.2.0/pkg/pymorphy/loader.go:35 +0x78
github.com/amarin/lexicon/basefetch.Fetch(...)
	.../basefetch/fetch.go:32 +0x7c
main.fetchBase(...)
	.../cmd/lexicon/dicts.go:73 +0x80
```

gomorphy's `pymorphy.NewLoader` calls the free function
`github.com/amarin/logging.NewNamedLogger`, which panics unless something in
the process has already called `logging.Init`/`logging.MustInit` to set a
global backend — `basefetch.Fetch` never does, and neither does
`cmd/lexicon`. This means `lexicon dicts fetch` — a documented CLI command —
is unusable as shipped, and so is `basefetch.TestFetch`
(`fetch_integration_test.go`, gated on `LEXICON_FETCH=1`) the one time it
actually runs against the network; both were apparently never exercised
end-to-end in Tasks 12/15 (network access was unavailable then, so the
`LEXICON_FETCH=1`-gated test was always skipped, and nothing else calls
`pymorphy.NewLoader`).

Worked around for this task by copying the real dictionary into the scratch
directory by hand (`cp .../pymorphy.dat "$D/base.opencorpora.dat"`, no
`.meta`) instead of running `fetch`, per the ruling to report a real-data
finding rather than silently paper over it. **Fixing this was out of Task
16's file scope** (`basefetch/fetch.go`/`cmd/lexicon/dicts.go` were not in
the brief's file list) — flagged here for the owner to pick up.

**Fixed** (separate follow-up task, commit `fix(basefetch): initialise a
logging backend for the pymorphy loader when the host has none`):
`basefetch/logging.go` adds an unexported, `sync.Once`-guarded
`ensureLogging()` that probes whether a `github.com/amarin/logging` backend
already exists (calling `logging.NewNamedLogger` inside a `recover()`) and
only calls `logging.Init(logging.WithLevel(logging.LevelWarn),
logging.WithTarget(logging.StdErr), logging.WithFormat(logging.FormatText))`
when none does, so it never clobbers a backend the host application already
set up. `Fetch` calls it before `pymorphy.NewLoader`. Covered by
`basefetch/logging_test.go`: one test reproduces the panic-turned-non-panic
by calling `ensureLogging()` then `pymorphy.NewLoader(t.TempDir())`, and a
second (run in a re-exec'd subprocess, since the backend is global process
state) checks that a pre-existing host backend's level is left untouched.

## Open questions still open

Of the plan's Q1–Q12, all but the following were resolved by an owner
decision during execution (see the D-table above and the plan file's
"Open questions" section for the resolutions):

- **Q3. Abbreviation lookup and profile kinds.** Kept as P1 parity (D16): a
  `name` profile without `abbrev` in its `Kinds` still expands «с.» via the
  abbreviation dictionary. Not reconsidered during v0.1; still open for a
  host that wants strict per-profile kind filtering.
- **Q5. gomorphy string aliasing.** `Registry.Parse` still defensively
  `strings.Clone`s `Reading.Normal`/`Tag` (D22). Not verified against
  gomorphy's actual guarantee during v0.1; dropping the clones is a future
  micro-optimisation once/if gomorphy documents that `Parse` never returns
  strings aliasing its internal mapping.
- **Q6. `Reload` cost.** `Reload` still reopens and rebuilds every
  dictionary unconditionally (D23) — no reuse of dictionaries whose
  file/content hash is unchanged. Acceptable for v0.1's dictionary sizes;
  a candidate optimisation for a host with many large TSVs reloaded often.
- **Q8. Defaults.** `DefaultCacheSize = 50000`, CLI `--rules` default
  `modern`, `Flag.String()` names (`ambiguous,predicted,unknown,abbrev,
  stop,reform`) were implemented as proposed and never revisited; still
  listed as "confirm" rather than a closed decision in the plan.
